# LISA_SUPER_INTELLIGENCE

LISA is a self-evolving edge AI. An ESP32-S3 runs a compressed Gemma-style model from an external W25Q128 flash chip and controls hardware over UART. A server on Render learns from everything the device does and ships improved models back over the air.

```
ESP32-S3 + W25Q128  ──telemetry──►  Render (FastAPI api + training worker)  ──►  Supabase (Postgres + Storage)
        ▲                                                                           │
        └──────────── signed OTA model / delta (verified, trial-booted) ◄──────────┘
```

| Folder | What it is |
|---|---|
| `server/` | Render service: API (`app/`), training worker (`worker.py`), scripts, tests |
| `render.yaml` | Render Blueprint: `lisa-api` (web) + `lisa-worker` (background worker) |
| `supabase/migrations/` | Database schema, storage buckets, role grants (run in order) |
| `edge/` | ESP32-S3 firmware: UART discovery, A/B model slots, ring log, OTA, telemetry |
| `gemma4/` | Inference engine, model format, W25Q128 driver, model image tools |
| `tools/fake_peripheral.py` | Simulated UART device for testing the board without real hardware |
| `docs/` | `ARCHITECTURE.md` (how it works) and `BRINGUP.md` (step-by-step testing) |

## Deploy on Render

1. **Supabase:** in the SQL Editor, run the three files in `supabase/migrations/` in order.
2. **Render:** **New → Blueprint**, pick this repository. Render reads `render.yaml` and creates:
   - `lisa-api`: web service, `pip install -r requirements.txt`, health check `/healthz`.
   - `lisa-worker`: background worker that trains with CPU PyTorch (`requirements-train.txt`).
3. Fill in the `lisa` environment group when Render asks:

| Variable | Value |
|---|---|
| `SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API → `service_role` key |
| `OTA_SIGNING_KEY_PEM` | the full contents of your OTA private key file (the one whose public key is in the device's `edge/secrets.h`) |
| `ADMIN_TOKEN` | generated by Render; use it as `Authorization: Bearer <token>` for admin calls |
| `TEACHER` / `ANTHROPIC_API_KEY` | optional: `claude` + a key to have Claude label data and classify unknown UART devices |

4. **Check:** `https://<lisa-api>.onrender.com/healthz` returns `{"ok": true, "ai": "LISA", "dev_mode": false, ...}`.
5. Put that URL into `EDGE_SERVER_BASE_URL` in the device's `edge/secrets.h`.

**Plans:**
- **Background workers** need a paid plan. The worker uses `standard`, because PyTorch training needs more than 512 MB of RAM. To exercise the pipeline without ML, set `TRAINER=mock` on a `starter` worker.
- **Web service:** keep it off the free plan. Free services sleep, and the device's 15 s HTTP timeout would hit the cold start.

## Firmware

```bash
cp edge/secrets.example.h edge/secrets.h     # then fill it in (never commit it)
python -m esptool --chip esp32s3 -p COM3 -b 921600 write_flash 0x210000 tokenizer.bin
pio run -e edge_node -t upload --upload-port COM3
python gemma4/w25q128_upload.py COM3 <model image>.w25img
```

## Tests

```bash
cd server
pip install -r requirements-dev.txt
python -m pytest -m "not slow"     # contracts with the firmware, API, pipeline, signing, deltas
python -m pytest -m slow -s        # trains LISA on CPU and checks it learned (~3 min)
```

## Secrets

Nothing secret lives in this repository, and `.gitignore` blocks the usual places:
- `server/.env`
- `server/secrets/`
- `edge/secrets.h`
- `*.pem`

The Supabase service-role key and the OTA private key belong only in Render's environment and your local `server/.env`. Anyone holding the OTA private key can push models to every device.
